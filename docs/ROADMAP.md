Source: spec `uu.txt` ("Three.js Game Interaction Skill"). Principle: **use Three.js to make the existing games more interactive, not to turn EduGame Studio into a 3D platform.** Scope agreed with the owner: **Skill + shared layer + a decorative backdrop/burst on every game** (quiz pilot first, then the rollout).

- [x] **Skill** — `.kilo/skills/threejs-game-interaction/` (SKILL.md + `references/{interaction-patterns,performance-guidelines,gameplay-integration}.md`), documenting the reusable patterns, lifecycle/disposal, the 2D fallback, and how 3D events wire into the existing handlers without re-implementing scoring.
- [x] **Load path** — `three@0.187.0` + `esbuild` bundle to `dist/src/renderer/vendor/three.global.js` (IIFE `window.THREE`, ~732 KB, local only — CSP `script-src 'self'`), `build:three` in the build chain, `<script>` in `src/index.html` before `gameplay.js`. `check:renderer-globals` skips `renderer/vendor/`.
- [x] **Shared layer** — `src/renderer/features/three-game-interaction.ts` → `window.threeGame` (`isAvailable`, `mount`, `unmount`, `setPaused`, `burst`, `addHoverEffect`, `addClickableObject`, `addObject`, `stagePoint`, `anchor`, `tween`, `effect`, `makeDestructible`, `makeUnlockable`, `makeConstruction`, `makeReactive`, `celebrate`, `on`, `emit`); scoring-agnostic, one rAF loop per handle, full disposal, `null` on failure = 2D fallback.
- [x] **Pilot (quiz + scenario)** — `gameplay.ts` mounts a world-tinted decorative backdrop at the end of `renderQuestion`, unmounts on question change and `closePlaySurface`, and bursts green/red on answer. Scenario inherits automatically (shared `renderQuestion`/`chooseAnswer`). 3D never scores, never changes answers; the DOM answer buttons stay the single input path. Verified `ui-three-game-check` **19/19**, unit `67/67`, screenshot confirmed.
- [x] **Rollout to the other 4 games (DECISIONS #138)** — treasure-hunt, race and matching now mount the same decorative backdrop and burst green/red on answer/match; scenario already inherits the quiz engine so it needed no extra work. Scoring stays in `game-engine/runtime.ts` (3D never scores). Race uses a `raceAnswerBurst` flag to carry the burst colour across its full board re-render. Verified `ui-three-game-check-4games` **41/41**, quiz `ui-three-game-check` **19/19** (no regression), unit `67/67`, `verify:css` **17/17**. `addClickableObject`/`addHoverEffect` remain unit-tested but not wired (per the spec's final principle).

Quiz/scenario pilot: a **construction tower** grows one block per correct answer, a **destructible block** shatters on a wrong answer, and the results screen **celebrates** on completion — all driven through one `reactThree(event, detail)` dispatcher that reads `state.gameAnswers` but never scores or changes answers.

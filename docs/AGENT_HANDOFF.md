# Agent Handoff — Start Here

You are taking over development of **EduGame Studio v0.3**. This file is the source of truth for product intent and known status. Inspect the code before assuming that a feature is complete.

## One-sentence product description
EduGame Studio is a Windows Electron + TypeScript app that helps teachers create educational games from lesson materials, stores games locally, and lets saved games play offline; cloud AI generation is mediated by a backend so provider keys are never shipped in the desktop app.

## Architecture map
- `src/main.ts`: Electron main process, local database, IPC handlers, document operations.
- `src/preload.ts`: allowlisted IPC API exposed to renderer.
- `src/index.html`: desktop window shell and ordered renderer script/style loading.
- `src/renderer/pages/`: individual screens (home, Giáo án/lesson plans, Dự án của tôi/my projects, game library, manual creation, lesson wizard, sessions/history, settings).
- `src/renderer/features/`: UI flows (local AI, game editor/play, result auto-save in `results.ts`, lesson wizard in `wizard/`). `treasure-art.ts` holds the built-in treasure SVG scenes/avatars and `game-audio.ts` the offline Web Audio effects + mute preference; both are loaded before `game-editor.ts`/`gameplay.ts` in `index.html`.
- `src/renderer/core/`: renderer initialization, navigation, and page wiring.
- `src/renderer/styles/`: global, layout, shared components, page-specific, and responsive CSS.
- `src/renderer/shared.ts`: shared renderer state and UI helpers.
- `src/shared/types.ts`: shared contracts/types.
- `src/services/` — game-service (normalize), game-validation (4 template validators), question-import (CSV/TSV/XLSX), ai-game-normalize (AI draft normalize), ai-game-design (treasure/race builder), and the lesson-to-game workflow: lesson-contracts/lesson-types (zod), game-project-adapter (draft ⇄ `EducationalGame`), lesson-store (sidecar tables + lesson files), ai-transport (typed errors + request registry), lesson-prompts/lesson-normalize/lesson-workflow (analyze/recommend/generate/regenerate-one-item), lesson-projects (wizard step machine), lesson-quality (advisory checks), lesson-chunker/lesson-retrieval (chunks + lexical/embedding retrieval), lesson-cache (O5 cache keys), lesson-item-repair (O5 one-item merge), item-capacity (O12 predicted 4–7 item counts; no AI call).
- `src/game-engine/runtime.ts`: game runtime (scoring, text answers, dedupe helpers).
- `server/index.ts`: Express AI Gateway scaffold.
- `server/schema.sql`: Supabase tables/RPC for usage quotas.
- `tests/`: unit tests (runtime, AI manager, model/runtime installer, model catalog, document-assist, question-import, game-validation, ai-game-normalize, ai-game-design, lesson-contracts, game-project-adapter, ai-transport, lesson-workflow, lesson-projects, lesson-quality, lesson-chunker, lesson-retrieval, embedding-catalog, lesson-cache, lesson-item-repair, lesson-prompts, lesson-store, item-capacity) run by `npm test`; `tests/smoke56-81.js` are CDP UI smokes (need `electron . --remote-debugging-port=9333` with `EDUGAME_USER_DATA=<empty folder>`; `smoke64/66/67` also need `EDUGAME_AI_TEST_DIR`; `smoke69/70` use port **9334** and synthetic data; `smoke71` checks treasure art/audio on port **9333**). `tests/manual/persistence71.js` is a two-phase write/verify check on port **9335** that must run write, quit, relaunch the same `EDUGAME_USER_DATA`, then verify. `tests/manual/real-ai-e2e.js` runs on port **9336** against a profile whose `edugame-data/ai-local` contains the downloaded Qwen model + llama.cpp runtime; it starts the runtime, cancels one analysis, verifies single-flight, then does a real analyze/generate/save/play cycle (about 3–4 minutes on the i5-10210U target).; `tests/manual/bench-ai.js` measures the real local model over HTTP (`analyze|generate|batch|thinking`) and writes `docs/BENCHMARKS.md` numbers — it needs a running `llama-server` and never runs in CI; `tests/fixtures/bench/lessons.json` is its synthetic Vietnamese lesson corpus; `tests/legacy/` holds older smokes kept for history.

## Do not break these invariants
1. Saved game playback works offline.
2. Game package `.egame` remains portable.
3. Renderer does not gain direct Node.js access.
4. No product-owned Gemini/OpenAI key or Supabase service-role key in desktop code or installer.
5. AI output is validated data rendered by trusted engines, not arbitrary executable code.
6. Quotas are checked server-side, not trusted from the desktop client.
7. Do not claim tests/build passed unless commands were run and results observed.

Rules to keep if you touch it:
- **Never give `setup-wizard-model.ts` an `import` or `export`.** `index.html` loads the renderer as classic scripts, `tsconfig` emits CommonJS (`module: Node16`, no `"type": "module"`), and a CommonJS file loaded that way throws `exports is not defined` before running a single statement (verified with `vm.runInContext`). `tests/setup-wizard-model.test.ts` loads the built file the same way and fails if this regresses. Shared contracts are restated as local `type` aliases; that test cross-checks the step list and the failure-code copy against the real `ai-core` modules, so drift is a red test.
- **The gate must never block the app.** It opens only when `setup:status` was read **and** `complete === false`. If the `setup:*` channels are missing or the read fails it stays closed for the session — an old build must not greet a teacher with a modal they cannot finish.
- **Preflight only after a successful status read.** On a failed read there is nothing to preflight for, and running it clears the error and substitutes a machine-check result, which looks healthy and fails only when the teacher presses "Bắt đầu".
- **`detecting` is not an interrupted run:** `preflight()` persists that step just by inspecting the machine, so treating it as one showed "lần trước chưa xong" on a healthy first install.
- Only `{ modelId }` crosses IPC — no paths, URLs or executables. No inline `onclick` (CSP `script-src 'self'`); clicks are delegated from `document` because every progress event re-renders the whole modal, and there is no ✕ (nor Escape) while a download is running.
- Unrecoverable failures (`blocked`: unsupported hardware/arch) deliberately have **no** "Thử lại"; they offer "Dùng không có AI" instead, because the app must stay usable offline.
